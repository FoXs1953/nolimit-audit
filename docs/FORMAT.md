# Формат эпизода NoLimit Audit 1.0.0

Для экспорта достаточно стандартной библиотеки Python. Команды запускаются из корня репозитория.

```sh
python -m auditlab.export --split train --out exports/train
python -m auditlab.export --split dev --out exports/dev
python -m auditlab.export --seed 54 --config config.json --out exports/example --private-out evaluator/example
```

При одиночном запуске `--config` необязателен. Пример файла для двух ошибок на одном платеже:

```json
{
  "scenario": "fx_period",
  "issues": {"fx_conversion": 1, "period_cutoff": 1},
  "period": "2026-10",
  "base_currency": "KZT",
  "timezone": "Etc/GMT-5",
  "invoice_count": 52
}
```

Для наборов `train` и `dev` экспорт создаёт по десять подкаталогов `01` … `10`. Пары публичных seed и конфигураций задаёт `open_configs`; официальный оценщик может выбрать другие значения. Отдельный эпизод сохраняется прямо в указанную папку. Повторный экспорт с идентичным содержимым допустим. При конфликте существующие файлы сохраняются, команда просит другую папку. Закрытая и открытая папки должны располагаться отдельно. Доступ агента к диску и каталогам оценщика отключается при запуске в изолированной среде.

## Что находится в открытом каталоге

| Файл | Представление и ключ |
|---|---|
| `manifest.json` | Версия, идентификатор, синтетическая компания, базовая валюта, период и часовой пояс, точность валют, округление, количество строк каждой таблицы и число документов. `record_count` считает проводки. |
| `policy.json` | Правила выбора даты курса, признания платежа, округления, назначения платежа и идентификации повторного счёта. |
| `ledger.csv` | Заголовок в первой строке. `row_id` идентифицирует запись, `journal_id` объединяет стороны одной операции. |
| `invoices.jsonl` | Один счёт на строку. В версии 1.0.0 `doc_id` совпадает с `invoice_id`, а `source_ref` идентифицирует исходный документ внутри контрагента. |
| `payments.jsonl` | Один банковский документ на строку. В этой версии `doc_id` совпадает с `payment_id`. Явная ссылка на счёт находится в `invoice_refs`. |
| `fx.csv` | Заголовок в первой строке. Для каждой комбинации даты, исходной и целевой валюты есть одна котировка. `row_id` позволяет приложить её как доказательство. |

Кодировка файлов UTF-8. В JSON отсутствующая ссылка имеет значение `null`. В CSV ей соответствует литерал `null`. При чтении CSV преобразуйте суммы из десятичных целых в целые числа, а отсутствующие ссылки в `null`. Котировка остаётся строкой.

Манифест задаёт период как полуинтервал от `period_start` включительно до `period_end` исключительно. Набор документов захватывает несколько соседних дат, чтобы можно было проверить пограничную проводку. Время события записано в ISO-8601 с явным смещением. Для локальной даты компания сначала переводит банковское время в `manifest.timezone`. Например, у зоны IANA `Etc/GMT-5` смещение UTC+05:00.

Число `amount_minor` выражено в минимальных единицах валюты. Курс показывает стоимость одной **основной** единицы исходной валюты в основных единицах целевой. Правильная сумма проводки в целых единицах рассчитывается один раз:

```text
round_half_even(payment_minor × rate × 10^(target_exponent − source_exponent))
```

Например, у KZT показатель 2, у JPY — 0. Значения курса, степени и суммы участвуют в десятичной арифметике. Отрицательная сумма банковского документа с видом `refund` отражает возврат. В книге дебет и кредит записаны двумя неотрицательными целыми полями. Одна операция балансируется в своей валюте.

## Происхождение данных и доказательства

В начале генератор строит счета, реальные для этой вымышленной компании платежи, возвраты, котировки и согласованные проводки. Затем он применяет причинные изменения. Каждое изменение можно отменить по истории в обратном порядке. Поля `before` и `after` фиксируют строку целиком, `before: null` означает вставку.

| Тип ошибки | Какие записи затронуты | Полный набор доказательств | Сумма ошибки |
|---|---|---|---|
| `duplicate_invoice` | Два ID счетов | Оба счёта с одинаковыми `entity_id` и `source_ref` и две первоначальные дебетовые проводки по `receivable` | Сумма лишнего начисления в валюте счёта. |
| `payment_allocation` | Счёт, платёж, его кредитовая проводка `receivable` | Для одной валюты — эти три записи. Для перевода между валютами дополнительно нужна дебетовая `cash` по этому же платежу. | Разница между поступлением и отнесённой частью в валюте счёта. Остаток записан на `suspense`. |
| `fx_conversion` | Платёж и связанная проводка `cash` | Оба ID и запись официальной котировки на локальную дату платежа для нужной пары валют | Модуль разницы между проводкой и корректной конвертацией в целевой валюте. |
| `period_cutoff` | Платёж и связанная проводка `cash` | Оба ID, содержащие сравниваемые метки времени | Модуль суммы платежа в валюте банка, если местные месяцы признания различаются. |

Два чистых платежа могут иметь идентичную сумму. Законные частичные платежи, различные исходные счета с одинаковой суммой и возвраты входят в обычные книги. Группы `fx_period` и `allocation_period` меняют два аспекта одного события. Общая конфигурация `issues` задаёт количество каждого типа. Суммарный предел — 12. Для явного взаимодействия счётчики должны предусматривать оба его типа.

Опция `--private-out` создаёт два файла. В `truth.json` записан список ошибок с суммами, валютой, затронутыми ID и допустимыми наборами доказательств. В `provenance.json` записаны версия генератора, seed, конфигурация и изменения публичных записей. Эти данные читает доверенный оценщик. Среди файлов открытого сайта их нет.

## Взаимодействие

В каталоге `docs/schemas/` лежат схемы [JSON Schema Draft 2020-12](https://json-schema.org/draft/2020-12). Внешние ссылки между схемами относительные к этому каталогу. Для автономного валидатора зарегистрируйте все JSON-файлы локально по их `$id`. Идентификаторы в домене `nolimit.example` служат именами схем.

| Схема | Что проверяет |
|---|---|
| `common.json`, `config.json` | Общие типы и конфигурация генератора. |
| `manifest.json`, `policy.json`, `records.json` | Манифест, политика и одна запись таблицы после типизации CSV. |
| `action.json`, `findings.json` | Рекомендуемые корректные вызовы пяти инструментов и тело терминальной отправки. |
| `reset.json`, `step.json` | Ответ Python API в виде массива либо сообщение JSONL-моста с именованными полями. |
| `trajectory.json` | Одна строка журнала. Поле действия может содержать исходный неверный ввод или `null` при внешнем прерывании. |
| `truth.json`, `provenance.json` | Два закрытых файла экспорта. |

Вызов `reset(seed, config)` принадлежит владельцу среды. Первое наблюдение содержит задание, манифест, политику и остаток шагов. Список записей возвращает до 50 строк и курсор той же таблицы. Чтение документа принимает `doc_id`. Калькулятор допускает десятичную арифметику. Неверный вызов инструмента расходует шаг. Результат шага содержит наблюдение, награду, флаги завершения, объект `info`. Максимум 100 действий, включая отправку. При тайм-ауте или исчерпании бюджета итоговый ответ пуст. В режиме eval наблюдения и награды, которые получает политика, не содержат промежуточного разбора. Время выполнения измеряется отдельно от воспроизводимой последовательности переходов.

Пример терминального действия:

```json
{"tool":"submit","findings":{"episode_id":"demo-mayak-2026-10","findings":[{"type":"payment_allocation","affected_ids":["INV-017","PAY-042","L-102"],"claimed_amount_minor":2000000,"currency":"KZT","evidence_ids":["INV-017","PAY-042","L-102"],"explanation":"Из платежа в 300 000 тенге на счёт отнесено 280 000."}]}}
```

До 30 выводов, 10 ID доказательств и 1000 символов обоснования на вывод. Порядок ID и внешние пробелы при сопоставлении игнорируются, регистр значим. Для TP требуются совпадение типа, множества затронутых ID, валюты, суммы в допуске и хотя бы один полный разрешённый набор публичных доказательств. Допуск у сгенерированных ошибок равен нулю. Любой неизвестный ID среди доказательств лишает вывод совпадения. Неизвестный непустой тип — допустимая по форме заявка, которую оценщик учтёт как FP.

Код в `auditlab/scoring.py` строит двудольный граф и максимальное взаимно однозначное сопоставление увеличивающими путями. При равных вариантах обход использует порядок отправленных выводов и отсортированные `issue_id`. Один повтор даёт один FP. Неверная структура отправки даёт −1. Формула для корректной структуры — `clip(2 × F1 − 1 − 0.002 × inspection_steps, −1, 1)`. Отправка исключена из стоимости исследования. При нулевом знаменателе P или R равны нулю. При пустых эталоне и ответе F1 равен единице, при пустом эталоне и непустом ответе — нулю. Полные семантические ограничения, включая доступность доказательств, бюджет и правильность арифметики, проверяет реализация среды.
