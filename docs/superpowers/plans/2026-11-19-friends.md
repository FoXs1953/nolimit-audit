# Friends Implementation Plan

> For implementation use subagent-driven-development with independent code ownership and a final integration review.

**Goal:** Bring consent-based sharing, friendships and shared discussions to the live NoLimit diary.
**Architecture:** Keep the existing offline diary and familiar routes. A same-origin Sites Worker uses trusted visitor identity, D1 for versioned sharing and relationships, and R2 for private media.
**Tech stack:** Browser ES modules, SQLite/D1, R2, Sites Worker, existing Playwright tooling.
**Spec:** [Approved friends design](../specs/2026-11-19-friends-design.md).

## Global constraints

RU, ҚАЗ, EN. A new day starts private. Only current authorized readers can read or respond. Loading a private day requires no account. Preserve the public site URL and the local ZIP workflow.

### Relationship and identity service

- [x] Map the session, profile, expiring invites, incoming and outgoing requests, symmetric friendship and removal to same-origin JSON endpoints. Index stable account IDs; use unique pair keys and conditional SQL on acceptance.
- [x] Verify anonymous browsing, two separate participating accounts, duplicate submissions and rejected/removed friendship.

### Published content and conversation

- [x] Publish allowlisted snapshots only after complete media staging. Authorize all feed, media, range and discussion endpoints with the current audience. Isolate ACL version updates from snapshot revisions.
- [x] Verify private, all and selected audiences, revocation, own-contribution removal, owner moderation and duplicate writes.

### Product screens

- [x] Add the Friends route, People/Feed sections, request/profile/publication/contribution screens and translated feedback. Reuse the day player in a reader mode.
- [x] Bind a local day to its first publishing account, offer a preview and audience controls; protect local deletion if network removal is unconfirmed. Add reactions and an accessible comment composer.
- [x] Verify a share at 320px and desktop, a return to the feed, an offline/private day and all three interface languages.

### Hosting and acceptance

- [x] Bundle the Worker, ship client assets, D1 migrations and private R2 binding. Exclude protected responses from persistent caches.
- [x] Use three isolated browser sessions with a real Worker/SQL/storage adapter to create friends, share a real photo/audio day, comment, add and remove audience, and reload.
- [x] Run existing diary tests, inspect the staged archive, publish the exact revision and verify the live route and unsigned session.
